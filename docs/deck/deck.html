The Story of AgentLeash

AI agents now pay for things themselves: data, APIs, compute, per call, over HTTP 402 ("x402").

To pay, an agent needs a key. A hot key is unlimited: one prompt injection, one bug, one leaked log, and the wallet is gone.

The usual fix is a custodial API with spending rules. Then you trust a server instead of the agent.

So we asked: can the network itself hold the agent to a budget, while the owner can still pull the plug at any time?

Benefits of AgentLeash

  • The owner sets the rules once, they become the contract address
    • budget per window of blocks, miner fees included
    • up to 3 allowed payees, a fee cap per payment
  • The agent pays on its own, no server holds the money
    • a tool answers 402, the agent signs a covenant payment, the tool serves
    • every payment carries an on-chain receipt bound to the HTTP request
  • The network says no, even to someone holding the agent key
  • The owner pulls the plug any time, without the agent's key
    • withdraw, top up, migrate to new rules
  • Tiny payments stay tiny: a pay tx is 700 bytes, 705 sats ≈ 0.2 US cent at 1 sat/byte
    • BCH ≈ 274 USD on 16.10.2026 (CoinGecko, read by the demo's own price tool)

BCH Usage

  • CashScript covenant on a P2SH32 address
  • State in one mutable NFT (CashTokens): elapsed | spent, 8 + 8 bytes
  • Transaction introspection fixes the shape: 1 input, back-to-contract + payment + receipt
  • Clock = proven UTXO age via relative locktime (CSV / BIP68), never the agent's word
  • Receipt: OP_RETURN "LSH1" sha256(nonce|method|url|body)
  • Owner path: any tx that also spends the owner's P2PKH coin
  • Owner wallet over WizardConnect; payments over x402 v2 messages, our leash scheme
function pay(pubkey agentPk, sig agentSig, int elapsedAdd) {
  // agent key, NFT category + capability, 3 outputs ...
  int outflow = tx.inputs[0].value - tx.outputs[0].value;
  require(outflow - amount <= maxFee);        // fee cap
  require(elapsedAdd >= 0 && elapsedAdd < 65536);
  require(this.age >= elapsedAdd);           // CSV: proven age
  int e = elapsed + elapsedAdd;
  int s = spent + outflow;                    // fees count
  if (e >= period) { e = 0; s = outflow; }    // window rolls
  require(s <= limit, "pay: limit exceeded");
  require(tx.outputs[0].nftCommitment ==
          toPaddedBytes(e, 8) + toPaddedBytes(s, 8));
}

Does it work? Tested like an attacker

183

automated tests (vitest, CashScript mock network that runs the covenant in the BCH VM), incl. 29 attacks with the exact rejection text and a property test of the worst case (2 × limit around a reset)

Real

chipnet runs with txids in the README: covenant, 402 paywall (also with 1 confirmation, a real block), web page, WizardConnect over the public relays, the agent

Unaudited

prototype; 7 automated review rounds by another vendor's model (Google Jules: contract, paywall, WizardConnect), each finding fixed with a test or documented; no professional audit yet

Traps we found and closed (each has a test):

fees outside the limitmany 546-sat payments burn several × the limit as fees → the limit counts payment + fee
CSV maskingBIP68 ignores bits above 16 and treats bit 22 as time → elapsedAdd < 65536
age off by oneage seen by the next block = tip + 1 − height, checked against a chipnet node
owner signaturethe owner input must be SIGHASH_ALL, else others could rewrite a withdrawal (documented)
fake "attack" on a fresh window(0, payment) is the honest state there → the demo does not build it (found while building the agent)
Will it make money?

Who pays, and why

  • Teams running AI agents that buy APIs and data
    • need a hard cap they do not have to trust, plus receipts per call
  • API sellers who want agent customers
    • a 402 paywall that settles in BCH, ~0.2 cent fee per payment
  • Wallets (Paytaca, Selene, Cashonize)
    • "agent allowance" as a wallet feature: distribution for us, a new use for them

Revenue to test (proposed, not validated)

  • Hosted 402 gateway for API sellers: a small take rate on settled payments
  • Managed leash for agent teams: policy templates, alerts, monitoring
  • Open core (MIT SDK and contract) keeps the trust story checkable

Why BCH: sub-cent fees for per-call payments, covenants and CashTokens on mainnet, no custodian in the path.

Honest status: prototype, no users, no revenue. Next: 5 conversations with agent builders before building more.
